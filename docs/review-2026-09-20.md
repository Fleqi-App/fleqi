# 2026-09-20 项目核查与 UI 优化

> 本文保留修复前的核查证据。后续已修复项和当前限制以 [实现与修复记录](implementation-2026-09-20.md) 及 [当前状态](status.md) 为准；下文“尚未修复”是核查时点的结论。

## 结论与范围

**当前不能确认首版产品能够按完整合同正确运行。** 分层结构与基础工程检查可用，输入条、会话、终端、设置和部分能力有真实实现；AI 规划、执行调度、会话结束联动、历史恢复及完整能力接线仍存在阻塞。此前“M3 后端与 UI 完成”“M4 完成”的表述不能当作整个产品验收完成。

本轮对照需求、UI、架构和能力合同，核查前端页面/状态仓库/宿主适配器、IPC 白名单、Rust 领域与应用服务、能力适配器、原生窗口以及现有验收脚本。未改参考工程或图标设计源。模型真实端点、发行签名、公证和 Intel 环境不在本次成功证据中。

## 已修复与 UI 优化

| 问题 | 改动与验证点 |
|---|---|
| 概览仍是工程诊断页，与六类能力工作区目标不符 | 恢复两列六类能力卡片，数量和操作名称取自 `catalogQuery`；点击进入同源分类；增加搜索、输入条件、无结果状态和文件设置入口。诊断信息保留在下方 |
| 小窗口侧栏占用过大、部分背景样式未定义 | 640px 控制台采用 64px 图标侧栏、卡片单列；补 `input/muted/primary` 语义 token；按钮不拆字；保留原深浅色基线 |
| 输入条初始化把写接口当作读取 | 删除两个挂载时的 `surfaceShow`，统一读 `surfaceGet`。事件和会话选择后重拉，切换后的提交与终端使用当前会话 |
| 72px 原生窗口裁掉窗口外的会话/终端/结果面板 | 新增 composer 专用 `surface_layout`，额外高度限定 0–480px、按所在显示器工作区限高；主条保持底部 72px，面板位于窗口内部；关闭恢复高度 |
| 键盘和终端实例生命周期 | 面板 Esc 关闭后归还输入焦点；xterm 内 Esc 仍直通；IME Enter 与在途重复提交不执行；终端按实际容器适配行列，连接完成后再次同步尺寸（修复面板已展开但 PTY 仍为 1 行的竞态）；原始输入串行发送，丢弃已关闭实例的迟到回执 |
| 提交后提前去重导致本次任务结果不显示 | 只在实际终态结果到达后去重；`bubbleSeconds=null` 保持常驻语义；失败结果不自动消失；终端模式不显示模型名 |
| 相同事件名连续到达不会刷新页面 | 在 store 中维护事件计数，任务、工具、模型、能力库按每次事件刷新；修复任务列表跨会话异步回执覆盖 |
| 等待批准没有可核查计划 | 增加只读 `run_plan_get` 与 Rust 生成的 `ExecutionPlan` 类型；任务详情显示步骤、目录字段、影响与未知范围；无计划/版本不符/空步骤不能确认；等待批准可取消 |
| Run 完成不发事件、取消被迟到的成功退出覆盖 | 完成后广播 `runChanged`；保留取消终态且不重复释放并发计数。旧测试的事件记录器实际上返回新空实例，本轮改为真实共享记录器并加断言 |
| 文档里程碑状态相互冲突 | 入口文档统一指向本报告和当前状态，不再把早期状态或局部测试等同于完整验收 |

会话历史面板本轮仅展示已有 AI Run 的只读记录和“继续为新会话”；完整对话、手动终端历史回放、收藏复用、能力参数表单仍不应宣称完成。

## 验证与复现

- `pnpm check`：文档、追踪关系、参考资产、仓库边界、Rust fmt/clippy/workspace tests（165 项）、DTO 一致性、IPC 边界和 TypeScript 通过。
- UI 行为与截图：Vitest 45 项；Playwright 11 项，包含 1080×760 概览、640×640 窄屏、760×72 输入条、560×432 会话面板、浅色设置、键盘焦点和 reduced-motion。截图仅为浏览器预览，不作为原生业务证据。
- 原生专门回归 `FLEQI_ONLY=run-ui pnpm test:desktop`：真实 WKWebView 中初始化保持 1 个会话；窗口展开到 432px，面板 top=8/bottom=352，主条 top=360/bottom=432；终端容器高度 301px；关闭回到 72px，宿主干净退出。终端另经真实 xterm 粘贴入口与 Enter → IPC → zsh 返回 `fleqi-ui-ok`，原始输出见 `ui-terminal-input.json/png`。证据 `tests/.artifacts/desktop/ui-window-regressions.json`、`ui-session-panel.png`、`ui-terminal-panel.png`。
- 完整原生矩阵：`pnpm test:desktop` 最终一轮通过，13 个 spec、34 项用例、9 次独立运行，包含新安装、Finder 真实驱动、设置/会话重启恢复和新增 UI 原生回归；每次宿主均干净退出。通过的是现有用例覆盖范围，不能抵消上文三项执行探针失败。
- 既有验收修正：Finder 贴附用例原来在新窗位置恢复动画之前采样，现对自建测试窗口设置固定坐标并等待稳定，几何断言保持不变。忙碌终端用例原来用空租约写入并吞掉错误，现先获取租约、等待提示符、构造真实目录差异并确认忙碌后再验证排队与取消。
- 独立执行探针：基于已有 `ProcessPort` 测试边界，给计划加入第二步；在首任务完成后调用 retry；持有四个运行任务再提交第五个并释放一个名额。三项均未达到合同结果（第二步未执行、retry=Queued、第五项=Queued），日志 `tests/.artifacts/audit-execution-probes.log`。临时探针源已清理；该证据验证服务调度，不冒充真实文件能力执行。
- 内嵌 WebDriver 1.4.0 的 `keys` 实现会在 keydown 已取消后继续发 input，并将小写字符 ASCII 作为 keyCode；xterm 场景会重复输入或误认功能键。因此原生回归使用 DOM 粘贴事件与正确 Enter 事件驱动真实 xterm 输入链路，不 mock IPC/PTY；物理逐键输入和真机 IME 仍留人工走查。
- 人工 VoiceOver、透明材质的不同桌面背景、跨显示器切换、真实用户模型端点、签名公证、Intel、性能 p95 和升级验签仍未验收。
