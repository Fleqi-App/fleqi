## 本轮修改

| 反馈 | 修改 |
|---|---|

| 菜单栏、Dock、重复打开 | macOS 使用 LSUIElement + Accessory；重复打开处理 Reopen，已有控制台显示并聚焦。关闭管理窗口保留宿主；手动隐藏输入条把焦点交回 Finder。 |
| 红绿灯 | 控制台和设置改用系统原生红绿灯与 overlay 标题栏，融入侧栏上部；删除第二套网页三灯。输入条红点仍是隐藏产品动作。 |
| 快捷键与闪烁 | 重启恢复实际快捷键注册；忽略按住产生的重复 Pressed；无效候选不先解除旧键，注册/保存失败恢复旧绑定并返回错误。相同上下文不反复发布或调整窗口尺寸。 |
| Finder 拖动与失焦 | WindowServer 几何观察替代 800ms AppleScript 几何轮询，检查间隔 50ms；松开鼠标且稳定后恢复。仅 Finder/输入条交互组可显示；管理窗口和其他应用焦点优先，系统暂隐保留同一会话。 |
| 选中 A 却处理 B | 表单打开时真实读取，AI/能力提交前核对展示过的快照，变化则 conflict，绝不自动替换输入。选区解析不完整时拒绝处理。PNG→JPG 的透明像素须显式选择背景合成，原图保留。 |
| 视频与材质 | 重新抽取 10.70–11.10s、93.80–94.10s 连续帧；加入锚定任务浮层、列表/详情横向过渡、提交淡出、面板关闭和原生窗口淡入淡出。macOS 26+ 使用 NSGlassEffectView，14/15 回退 vibrancy；关闭透明度/减少透明度使用不透明表面，减少动态直接结束过渡。Windows 使用普通组件材质。 |

视频提供结构、锚点、方向与大致时序证据。scale .24、220ms、原生淡入 180ms 等是本轮实现值，不冒充测得了视频原始弹簧参数。Windows/Intel/旧版 macOS 的实机效果仍需对应设备验证。

## 后端合同核对

| 合同范围 | 核对结果与实现位置 |
|---|---|
| UI/宿主边界与 DTO | UI 的宿主调用仍集中在 adapters/host；数据库、进程、网络和凭据在 Rust；83 个生成 DTO 一致，宿主命令白名单一致。 |
| Finder 与输入绑定 | context_service 序列化采集、对相同输入去重并保留固定快照；commands_m3 的 capability_form、capability_submit、run_plan_submit 真实刷新/校验；平台读取拒绝解析数量不一致的选区。 |
| AI 与手动终端 | execution 的策略判定依实际步骤与命令可信分类，不信模型自报 read；手动 `!` 与 PTY 原始输入仍独立于 AI 规划。 |
| 执行与恢复 | run_service 保留四个并发上限、FIFO、多步骤结果与取消；恢复将未完成任务标为中断，不自动重放。确认绑定计划版本和输入版本。 |
| 会话与终端 | 显式再唤起新会话，系统暂隐复用会话；结束联动取消规划、Run、PTY。输入租约、忙碌 pending 目录、排队撤销和幂等回执仍保留。 |
| 模型连接 | 预设不保存虚构账户/模型；密钥仍在 Keychain，前端只接收配置状态。修正手写 URL 拆分，使用实际 URL host 校验，支持 IPv6 回环，拒绝用户信息/查询凭据；连接探测也执行同一校验。 |
| 文件能力 | 本地表单→计划→确认→native 执行仍为真实路径。A/B PNG 改选已用真实 Finder 点击、真实 IPC、JPG 像素核验，旧快照被拒绝且只生成 B 的蓝色结果。 |

后端主要结构符合分层和执行合同，但完整首版仍有差距：历史界面只显示最近记录，完整分页/回放与 Run 输出流、细粒度进度未收口；睡眠/唤醒的完整关联仍欠缺；真实云模型质量、ASR/OCR 环境与受控系统操作仍有 33 条扩展条件验收。凭据存储和数据库跨资源更新失败时的原子恢复也需要进一步补强，不能据当前成功路径宣称所有失败场景已覆盖。

## 第四轮：普通 App 启动、同名处理与输入条抖动

原先 `LSUIElement=true / Accessory` 让 Fleqi 直接作为菜单栏应用启动，因此没有普通 Dock App 的启动表现；不是安装包损坏。这轮主包改为 `LSUIElement=false`，管理窗口打开时使用 Regular，最后一个管理窗口关闭后转为 Accessory 保持菜单栏常驻，再次打开恢复 Regular；系统决定 Dock 启动动画，不人为请求连续弹跳。

“重名冲突”的原错误来自前端发送 `overwrite`，而 Rust 枚举只接受 `uniqueName`。现已打通 DTO、保存、固化计划和原生文件输出，并将文案改为“遇到同名文件时 / 保留两份 / 替换已有文件”。替换先在目标文件系统生成完整输出，再发布；旧文件保留到发布成功，失败尝试恢复，恢复失败保留备份并报告路径。原始输入、同名文件夹与图片目录批处理仍保留安全命名。普通手动终端不受该设置约束。

输入条尺寸在 AppKit 主线程一次读取并更新，连续展开/收起不使用过时 frame；重复可见性事件不重新开始淡入淡出。Finder 拖动/失焦暂隐立即完成，主动关闭保留淡出；立即隐藏时先移出屏幕再重置透明度，避免闪回一帧。
