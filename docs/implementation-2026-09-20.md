# 2026-09-20 实现与修复记录

本轮接续 [项目核查](review-2026-09-20.md)，已修复主要执行阻塞并补齐扩展能力执行入口。**实现入口齐备不等于完整首版验收通过**；模型、语言包、受控外部操作与发行环境仍有条件项，另有本文明确列出的工程收尾。

## 已实现

- 执行服务按 FIFO 调度，最多四个活动任务，顺序执行 script/process/native，记录逐步状态；中途失败保留真实结果，取消不会提前释放容量。真实进程验证工作目录、多步骤、重试、排队、失败与取消。
- Run 持久保存计划、目录、输入版本与请求回执。重启只中断遗留任务，不重放命令；历史按需读数据库，完成输出从活动缓存释放。审批/开始前核对输入元数据，已替换的文件不能沿用旧确认。
- 规划服务注入真实目录、选区、命中规则与能力目录；默认/摘要模型联合绑定端点和模型，拒绝歧义或失效选择。模型上报 read 不能绕过实际命令分类。
- 会话结束统一取消规划/Run/PTY；终端显式取消订阅及匹配令牌释放，旧页面不能夺走新租约。手动 cd 后 ! 命令使用实际 cwd，pending 时使用最新目标。宿主退出排空任务和存储。
- 会话创建/继续/选择/结束/结束全部/删除使用持久请求回执。创建与删除的数据库修改和回执同一事务提交；不同载荷复用 ID 明确冲突。历史 Run 重试创建关联新会话，不沿用旧确认。
- 目录共有 111 个独立 CAP ID，对应 135 条能力验收用例。能力库表单→固定输入→计划→确认→native 执行→真实结果已接通。目录和表单同源；原 50 项扩展 gap 已具备执行路径。
- 补齐图像/媒体/文档/PDF、文件检索整理、Git、Homebrew、系统/网络和计算能力。图像目录批处理限定范围；JPEG 透明度必须明确合成策略。OCR 检查每个请求语言，不静默降级。PDF 合并保留完整对象图及继承资源，正文/页序有真实断言。
- PDF 口令仅以短期引用进入计划，通过 stdin 传递给工具，不放入 argv/落盘计划。文件输出遵循源文件旁或自定义目录；明确输出目标进入计划。工具执行器优先使用工具服务实际检测到的受管路径。
- UI 修复原生浮层裁切、隐式新建会话、重复事件刷新、终端尺寸/焦点/租约、IME 提交、结果气泡和任务定位；能力搜索、参数表单、四类规则范围、规则编辑/启停、AI/手动收藏复用、最近 100 条会话内容已接通。
