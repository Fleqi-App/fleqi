# Fleqi 宣传片实机录制清单

状态：计划，尚未执行采集。对应 [分镜](storyboard.json)。用户已要求先审方案，审阅后再进入录制。

## 拍摄环境

使用当前 Fleqi 的原生 macOS App，选定构建后记录版本、二进制哈希与工作区状态。普通浏览器页面只能帮助看布局，不能作为 Finder、模型、终端或执行效果的拍摄来源。现有 `tests/desktop/specs/14-workflow.spec.ts` 使用模型 fixture，其截图可了解面板位置，不能当真实 AI 演示。

先建立一个独立演示目录，建议 `~/Movies/Fleqi-Demo/Images`。仅向其中放入两张可公开的自有截图副本：`Console.png`、`Finder.png`。不对原附件和日常 Downloads 目录执行转换、覆盖或删除。演示页不展示真实密钥、账号或无关文档。

已检查原附件的 alpha：控制台截图范围为 0–255，含透明区；Finder 截图全为 255。控制台图片可直接用于片中窗口构图，但主任务的两张输入图使用重新采集的不透明实机截图，以避免在未指定背景色时暗自合成透明像素。两张图片内容均应来自真实 App。

全景优先录制原生 Retina 帧缓冲，30 或 60fps；最终统一为 30fps。先确定 16:9 安全构图，再调整真实窗口大小与系统显示缩放。Finder 与输入条完整同框时，主界面需要清晰；输入框和任务面板不足以支持特写时单独录近景。目标是源像素覆盖输出像素，不保证当前显示器一定能录到原生 4K。

每段保留动作前后至少两秒。全流程原始录屏不断开，剪辑可以压缩等待，但不能把真实确认、失败或必要步骤剪成“自动完成”。压缩明显等待时用自然剪辑，必要时标记“等待已缩短 / Wait shortened”，不宣称视频中的时长就是产品性能。

Finder 橙色选区以拍摄机实际主题为准；Fleqi 采用附件对应的浅色界面和真实原生材质。不要修改 UI 代码来迎合参考片。App 自身的 140–520ms 动效直接录制，后期相机单独运动。

## 必须先跑通的主任务

1. 在演示目录放两张不透明 PNG，记录大小、像素尺寸、SHA-256；清理动作只影响这个任务创建的演示文件。
2. 在 Finder 选中两张图，确认输入条读到正确目录和两项选区。
3. 通过已经配置的真实模型执行自然语言请求。AI 路径可以产出 script/process/native 计划，画面忠实展示实际路径。
4. 人工检查计划确实只处理这两张图，输出 JPG、目标宽度 1600、原件保留；确认并录制执行。
5. 独立解码输出、检查尺寸、数量、原件哈希；之后才录结果镜头和“原图保留”的字幕落点。
6. 用新的独立目录副本完成英文 take，避免同名输出和前一遍状态干扰。
7. 返回中文或英文已验证结果，录制手动终端部分。两版命令相同；若正文有语言差异，使用各自连续 take。

真实模型路径若失败，先记录并解决相应配置或任务问题，不能用本地表单成功画面拼成 AI 成功。必须改脚本或改卖点时回到方案修改；不能把“实现了 API”当作拍摄完成。

## 局部采集与后期边界

每个重要状态需要一张完整窗口 PNG 和一份坐标记录：窗口、Finder 内容区、输入条、选区、任务面板、确认按钮、结果、终端的 `x/y/w/h`，并写明逻辑点与物理像素比例。后期裁片由这些记录生成。

可以做：真实截图裁片、透明窗口边界遮罩、相机透视、景深、柔光背景、片外标题字幕、把同一时刻真实 UI 局部向前移。

不能做：重绘 Fleqi 页面、改按钮文案冒充英文版、合成终端输出、伪造进度百分比、让截图中的光标点击并不存在的交互、把 fixture 或截图拼接成真实模型成功过程。

输入条与 Finder 的原生关系必须清晰：输入条位于 Finder 下方，任务/终端面板向上展开。后期应把整组窗口作为同一空间对象；独立局部特写离开原位时使用原片那样明确的摄影展示方式，不能误导为新的产品布局。

## 录制结束的证据包

- 选中源文件、输出文件及各自哈希/尺寸/格式，中文英文各一份。
- 实际 App 版本、构建哈希、录制分辨率、fps、显示缩放、主题与关键设置。
- 每镜头来源 take、入点/出点、是否缩短等待及缩短区间。
- 原始连续录屏、无缩放关键帧、局部坐标表；不把含凭据的日志放入成片工程。
- 记录需要重录的状态或材料，完成后只清理本任务的临时产物。
