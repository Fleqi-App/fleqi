# macOS 更新后的重新授权

2026-09-23 用户明确要求：更新安装后清除 Fleqi 的 macOS 隐私权限，由用户自行重新授权。

普通安装构建在权限服务和 Finder 上下文初始化前核对自身 bundle 标识与代码签名 CDHash。构建身份变化时（包括相同版本号重新打包）调用系统 `tccutil reset All app.fleqi.desktop`，只处理 Fleqi 的 TCC 隐私授权，不删除配置、历史、API 密钥或其他应用授权。

成功后在应用数据目录的 `permission-build.txt` 记录构建身份。同一构建正常重启不重复清理。失败时不推进记录；权限探测显示失败，可通过权限页的显式申请重试，不能沿用旧状态并伪称清理成功。开发可执行文件及 desktop-test 构建不清除普通应用的授权。

该流程独立于交付方式：手动替换和后续自动更新安装的新构建都覆盖。安装器应先替换应用并退出旧进程，再启动新版本；新版本须在使用相关能力之前完成重置，不自行重新授予权限。

2026-09-25 的 0.0.2 测试版加入 Tauri updater、固定 HTTPS 更新源与验签公钥、启动检查和显式安装。下载验签失败不安装、不重置权限；只有安装成功后的新构建首次启动才重置权限。发布状态及验收范围见[发布与自动更新](releasing.md)，正式签名、公证与跨系统升级仍属 M5 未完成项。

实现入口：`crates/fleqi-platform/src/macos/update_permissions.rs`、`permissions.rs` 和 `apps/desktop/src-tauri/src/state.rs`。测试覆盖首次处理、同构建去重、构建变化、失败后重试以及开发程序隔离；测试不调用真实权限重置。

本机验证（2026-09-23）：普通包首次启动成功写入与新签名匹配的构建记录；安装到 `/Applications/Fleqi.app` 后再次执行限定 bundle 的系统重置，返回成功。启动后 Finder 自动化与辅助功能均显示“未授权（系统尚未询问）”，没有代用户授权；第二次启动未改写已成功的构建记录。签名、普通包启动/退出、平台测试、类型与 Clippy 检查通过。证据位于 `tests/.artifacts/permissions-update-2026-09-23/`。
