# Fleqi 产品需求与验收合同

版本：1.1 · 日期：2026-09-16。状态：本轮确认的首版开发基线。项目许可证：AGPL-3.0-only。

本文定义产品行为和发布验收；[能力台账](capabilities.md) 定义逐项操作意图与输入输出；[界面设计](ui-design.md) 定义 UI；[架构](architecture.md) 定义实现边界；[开发计划](development-plan.md) 定义实施顺序。入口与资料优先级见 [文档索引](README.md)。

P0 工程准备与产品实现分开；首版范围和默认值不因排期改变。当前实现与验证见[实施状态](status.md)。

## 1. 产品范围

Fleqi 是开源的通用桌面命令助手。用户在 Finder 文件上下文中，通过自然语言、以半角感叹号进入的手动命令，以及持续交互终端完成文件、系统、开发、网络、计算和消息任务。独立输入条是日常操作主入口；工作区是通常隐藏的控制台，用于预览、配置、管理和少量操作。

首发平台为 macOS，首版交付本合同的完整功能和全部能力台账。Windows、Linux 后续发布，复用 Rust、Tauri 2 和同一套 Web UI，并单独完成平台适配与验收。普通浏览器不是实际产品运行环境。

2026-10-06 Windows 修复范围：仅 Windows 11 x64；交付输入条、Explorer 当前窗口及活动标签页的目录/选区/跟随、系统凭据、PowerShell 5.1 持续终端与 AI 执行，以及基础文件、回收站、ZIP、图片和 PDF。Windows 本轮开放清单见能力台账，其余条目必须在 UI 标注不可用并由后端拒绝；不因此缩减 macOS 合同。媒体、OCR、转写、扩展工具自动安装和 Windows 自动更新不属于本轮。保留设置值 `followFinder`，Windows 显示为“随资源管理器”；默认值不变。

首版包含六类 30 项基础文件能力，以及历史目录 10 类 105 项操作意图。条件能力必须在首版具备实现、条件检测和错误处理；未连接硬件、未授权或没有外部账号不构成将实现延期的理由。每个平台的正式版都必须提供真实文件处理能力。

首版不包含订阅、试用、商业授权、许可证激活、强制登录或 Fleqi 自营模型代理服务。实时语音在下一版本实现；文件转写、字幕和 OCR 属于首版能力，与实时语音无关。

2026-10-07 Linux Bash 补充范围：在受支持的 Bash 5.1、5.2.11 及以上的 5.2、5.3（Readline 8.1–8.3）中实现安全自动目录同步。只有主提示符、编辑行为空且会话可见时才能切换；输入、续行、交互程序和 `read -e` 不被目录控制内容打断。暂隐暂停，后台取消未执行请求，恢复时重新核对最新目录。版本不兼容、编辑器钩子冲突或控制通道失效时明确显示状态未知，保留终端原始输入并引导手动操作，拒绝未经确认的输入条 `!` 投递。此项不代表 Linux 桌面环境、安装包或完整产品验收。

## 2. 术语与固定值

| 术语 | 定义 |
|---|---|
| 输入条 | 独立原生窗口中的 UI-COMPOSER，负责新任务、手动命令、当前上下文和会话切换。 |
| 控制台 | 平时隐藏的工作区窗口，管理记录、能力、规则、收藏、工具与设置。 |
| Session | 一次持续对话，包含 AI 任务、目录上下文和生命周期；可以没有 PTY，首次需要终端时按需创建至多一个 PTY 并关联其输出。 |
| Run | 一次 AI 请求的计划、授权、工具调用、执行和结果记录。 |
| 活跃会话 | 尚未结束的会话，可以在前台或后台；后台会话不是历史只读记录。 |
| 历史会话 | 已结束会话的持久记录；继续时创建有关联关系的新 Session。 |
| FinderContext | 有效目录、选中项、视图类型及更新时间组成的快照。 |
| appliedDirectory | PTY 已确认切换到的实际目录。 |
| pendingDirectory | Finder 最新目标目录；终端尚不安全或尚未确认切换时保留。 |
| 主动隐藏 | 用户点击隐藏/关闭主栏或用快捷键明确执行隐藏。 |
| 系统临时隐藏 | Finder 移动、焦点/空间切换或系统状态造成的暂时不可见，不等同主动隐藏。 |
| activation | manual 或 followFinder，默认 manual。 |
| hotkey | 用户录入且由宿主成功注册的快捷键；允许未绑定，注册失败的候选不算有效绑定。 |
| hideBehavior | keepAll 或 endAll，默认 keepAll。 |
| aiPolicy | yolo 或 readOnlyAutoConfirmChanges；默认后者，仅约束 AI 操作。 |

### 2.1 设计默认值：唯一来源

下表是本轮设计默认值，首版有效；后续只能通过需求变更调整。UI、架构、配置初始化及验收引用本表，不另外维护冲突的默认值。

| 字段/限制 | 默认值与有效范围 |
|---|---|
| barEnabled | true。 |
| activation | manual；允许 manual / followFinder。 |
| hotkey | null，即未绑定。只有真实注册成功的候选才成为有效绑定。 |
| hideBehavior | keepAll；允许 keepAll / endAll。 |
| aiPolicy | readOnlyAutoConfirmChanges；允许 readOnlyAutoConfirmChanges / yolo。 |
| launchAtLogin | false。 |
| theme | dark；支持 dark / light / system。 |
| bubbleSeconds | 4.8；允许 1–30 秒或 null（常驻）。 |
| inlineSuggestionsEnabled | true；关闭只隐藏条内建议，不移除能力浏览入口。 |
| inlineSuggestionsLimit | 3；允许 1–5，实际显示数量还受可用空间限制。 |
| transparency | true；系统减少透明度及平台材质能力优先，可退为不透明表面。 |
| motionMode | system；允许 system / reduce，不能用应用设置强制忽略系统减少动态效果。 |
| providers | 空列表；用户自行配置 API 或本地服务。 |
| defaultModel | null；用户保存有效配置后显式选择。 |
| summaryModel | default，即跟随 defaultModel；允许单独指定有效模型。 |
| terminalFontSize | 13；允许 11–20，变化后同步更新终端行列尺寸。 |
| outputLocation | besideSource，即默认在源文件所在目录生成新文件；需要单一输出位置的能力先明确显示目标目录。 |
| nameConflict | uniqueName，即保留已有文件并生成不冲突的新名称；可选 overwrite，新文件完整生成后替换同名输出，原始输入文件和同名文件夹保留。替换意图写入计划并按 AI 策略确认。 |
| conversionSourceHandling | keep，即转换后保留原文件；可选 trashAfterSuccess，只有对应新文件生成并校验成功后才将原文件移入回收站。 |
| AI 并发上限 | 4；超出进入可见队列，不丢弃请求。 |
| 活跃 Session 上限 | 16；达到上限时提示结束已有会话，不静默终止或复用旧会话。 |
| 一次显式选中项上限 | 1000；超限需缩小选区，不截取前 1000 项冒充全部。 |
| 输入历史上限 | 200 条。 |
| 普通结束历史保留 | 30 天；置顶会话及其历史不自动清理。 |
| 每 Run 输出保存上限 | 50 MiB。 |
| 每 Session 终端输出保存上限 | 100 MiB。 |
| 屏幕 scrollback | 10000 行；保留范围内的更早历史从日志分段读取。 |

达到输出保存上限时须明确标注截断及保留范围，不伪称全量保存；屏幕滚动缓冲与持久输出限额分别执行。清理不删除用户输入或生成的文件。仅在没有额外前置条件时使用上述默认值；例如 manual 且 hotkey=null 仍按 FR-ENTRY-003 引导设置，不能因 barEnabled=true 自动显示。

## 3. 入口、显隐与窗口

| ID | 必须实现的行为 | 可验收场景 |
|---|---|---|
| FR-ENTRY-001 | 输入条为日常主入口，控制台通常隐藏；托盘/菜单栏提供显式打开、设置和退出入口。 | 从托盘完成唤起和一次任务；无需先打开控制台。 |
| FR-ENTRY-002 | barEnabled=false 时，自动显示、快捷键和菜单唤起都不能显示输入条；设置仍可打开。用户将 barEnabled 从 true 改为 false 属于显式关闭，按当前 hideBehavior 处理一次；重复的 false 状态和系统 temporarilyHidden 不触发该处理。 | 关闭开关按 keepAll/endAll 保留/结束会话；重复收到禁用状态不重复处理，系统临时隐藏不结束会话；入口提示先启用。 |
| FR-ENTRY-003 | activation=manual 默认不自动显示；没有已成功注册的 hotkey 时，菜单显示入口引导快捷键设置，不显示主栏。注册成功后才能按手动入口唤起。 | 全新配置无快捷键，Finder 变化不自动出现；点击菜单显示进入设置；完成真实注册后显式唤起新会话。 |
| FR-ENTRY-004 | activation=followFinder 独立于快捷键是否绑定；在权限允许、存在有效目录且未被主动隐藏抑制时自动显示。 | 不绑定快捷键也可随 Finder 自动显示；缺权限或无目录时显示适当状态而不伪造上下文。 |
| FR-ENTRY-005 | 用户主动隐藏自动显示的输入条后，抑制自动重现，直到下一次显式唤起或改变 activation；普通 Finder 切换不解除抑制。 | 主动隐藏后切换窗口、选区或目录均不立即弹回；显式唤起恢复。 |
| FR-ENTRY-006 | Finder 移动期间临时隐藏输入条，放下后在符合显示条件时重新定位显示；不结束或新建会话，不改变主动隐藏抑制状态。 | 移动 Finder 时运行中的终端继续工作，放下后恢复同一当前会话。 |
| FR-ENTRY-007 | 自动显示已有的当前会话或为首次自动显示创建会话；不能因为焦点/窗口变化从后台会话中擅自选择另一会话。 | keepAll 主动隐藏留下的旧会话不会在另一个 Finder 窗口自动冒出。 |
| FR-ENTRY-008 | 关闭设置/控制台不退出 Fleqi；退出 App 结束其管理的 AI 工作和 PTY，并持久化历史。 | 关闭设置仍可从托盘唤起；退出后没有由 Fleqi 管理的残留终端进程。 |
| FR-ENTRY-009 | 多显示器、空间切换、休眠恢复及 Finder 关闭后重新判断有效窗口与显示条件，避免抢焦点和错误贴附。 | 恢复后输入条不留在失效屏幕位置；主动隐藏抑制仍有效。 |

## 4. Finder 上下文与终端目录

| ID | 必须实现的行为 | 可验收场景 |
|---|---|---|
| FR-CTX-001 | 读取当前有效 Finder 文件夹、选中文件及视图类型；显示当前任务使用的目录和选区摘要。能力表单打开时刷新，提交核对已展示快照；不完整选区拒绝处理。 | 同窗口 A→B 改选后只处理 B；旧快照提交拒绝并要求重新核对，不悄悄替换输入；搜索/虚拟位置不能被猜测为有效执行目录。 |
| FR-CTX-002 | 只有当前可见会话随活动 Finder 文件夹自动同步目录；没有 PTY 时只更新工作上下文。会话退到后台或 keepAll 隐藏时取消尚未投递的自动目录切换与 queuedLine，手动命令保留为该会话草稿；已运行的 AI/PTY 继续。已投递请求的晚回执可更新真实 cwd，但旧/后台回执不能投递后续命令。 | A 当前、B 后台时仅 A 自动同步；A 忙碌时隐藏后，即使回到安全提示符也不在后台自动切目录/发命令，显式恢复后重新按当前 Finder 同步。 |
| FR-CTX-003 | 只有 shell 位于已验证的空闲提示符且命令行为空时，宿主才可安全传入目录切换；不能仅靠输出文本像提示符就判定安全。 | vim、密码输入、交互 REPL、前台命令及有未提交输入时均不会收到目录切换输入。 |
| FR-CTX-004 | 终端不安全时仅更新 pendingDirectory；多次 Finder 切换只保留最新目标。安全提示符恢复后自动应用最新目标。 | 程序运行时依次切换 B、C，程序结束后只切到 C，且不打断程序。 |
| FR-CTX-005 | 目录同步确认前明确显示最新目标、同步中/等待终端空闲及实际目录差异；确认后更新 appliedDirectory。 | Finder 指向 B、终端仍在 A 时，UI 不能显示成已在 B；权限失败保留错误和实际目录。 |
| FR-CTX-006 | 从输入条提交的新手动 ! 命令必须绑定提交时显示的目标目录并等待其同步成功；等待期间可取消。若 Finder 再换目录，撤销该命令自动投递、保留为草稿并提示重新提交，不能改投新目录或在旧目录静默执行。 | 对 B 提交的命令等待同步期间切换 C，命令不执行到 B 或 C；目录可继续同步 C，用户复核草稿重新提交后才执行。 |
| FR-CTX-007 | 终端面板的原始输入始终可继续控制当前程序，不受 pendingDirectory 等待阻塞。 | 等待目录同步时仍能向 vim、密码提示或交互程序输入，Ctrl+C 仍到达 PTY。 |
| FR-CTX-008 | AI 新任务绑定提交时 UI 显式显示的最新 FinderContext；手动 cd 仅改变 PTY 实际目录，不把新 AI 任务暗中改到该目录。已在执行的 Run 保持原快照，不随 Finder 切换改输入或工作目录。 | Finder 为 A，终端手动 cd 到 B 后新 AI Run 仍使用明示 A；再切 Finder C，新 AI 用 C；旧 Run 保持各自原快照。 |
| FR-CTX-009 | 选择后台活跃会话时保留其对话、输出和程序，并按当前 FinderContext 请求目录同步；若其终端忙碌，使用同一 pendingDirectory 规则。 | 从 B 后台会话恢复到当前 Finder C，历史不丢；程序忙碌时不强行切目录。 |
| FR-CTX-010 | 新建 Session 的初始工作上下文来自当前 Finder，不强制启动 shell；首次打开终端或提交 ! 时在当时有效目录创建 PTY。无有效目录时要求选择目录，并在选择前不启动依赖目录的任务。 | 纯 AI Session 没有 shell 子进程；首次使用终端后才创建 PTY。无可用目录时提供选择入口，不以用户主目录替代。 |
| FR-CTX-011 | 路径由宿主以安全参数通道传递，包含空格、引号、换行、Unicode 或命令符号的目录也不会变成额外命令。 | 使用这些名称的真实测试目录完成同步，目录名内容不被执行。 |
| FR-CTX-012 | 结果支持列出文件、打开目录及在 Finder 定位/选择；不能一次呈现跨目录选区时按目录分组并说明。 | 多目录搜索结果全部可见且可逐组定位，不能丢失不能直接选中的结果。 |

## 5. 持续多会话

| ID | 必须实现的行为 | 可验收场景 |
|---|---|---|
| FR-SESSION-001 | 支持同时保留多个持续 Session，每个具有独立对话、输出、目录、Run 和生命周期，并可按需拥有一个 PTY。纯 AI 对话是完整会话，不要求先启动 shell。 | 两个会话分别运行交互程序和纯 AI 工作，输入输出不串线，纯 AI 会话无额外 shell。 |
| FR-SESSION-002 | 手动唤起输入条总是新建 Session；keepAll 下再唤起不自动恢复旧 Session。 | 隐藏前为 A，再显式唤起得到 B，A 仍可从选择器主动恢复。 |
| FR-SESSION-003 | 输入条右侧提供视频风格气泡选择器，显示活跃与历史会话并明确状态；切换保留已有内容。 | 用户能分辨后台运行、等待、已结束，选择目标后显示对应记录。 |
| FR-SESSION-004 | hideBehavior=keepAll 时主动隐藏保留全部活跃会话、AI 任务和 PTY，隐藏后旧会话不在其它 Finder 自动显示。 | 后台长任务继续完成；切换 Finder 不弹回；显式唤起新建且可主动恢复旧会话。 |
| FR-SESSION-005 | hideBehavior=endAll 时主动隐藏结束全部活跃会话、AI 任务及 PTY，保留历史；设置持续生效，不逐次询问。 | 多会话均进入结束状态，执行中的任务收到取消/终止；没有每次隐藏确认弹窗。 |
| FR-SESSION-006 | 系统临时隐藏不执行 keepAll/endAll 的终止语义，不把当前会话转为历史。 | Finder 拖动期间即使配置 endAll，交互程序仍保持运行。 |
| FR-SESSION-007 | 当前会话可以单独结束：停止其任务和 PTY，保留历史，不影响其它会话。 | 结束 A 后 B 仍可继续交互，A 输出可回看。 |
| FR-SESSION-008 | 历史只能查看或继续为关联的新 Session；继续时使用当前有效 Finder 上下文，不恢复旧进程；PTY 仍按需创建，不因历史曾有终端就立即启动 shell。 | 从历史 H 继续得到新 ID，关联 H；纯 AI 继续没有 shell，旧任务不自动重跑。 |
| FR-SESSION-009 | 重启恢复历史、设置及关联关系，不重新运行 shell、AI 任务、安装或其它旧进程；原活跃记录标为中断/已结束。 | 强制退出后重启能回看，进程列表没有自动重跑的旧任务。 |
| FR-SESSION-010 | 图钉仅影响会话及其历史的排序，不改变原生窗口层级；左侧提供删除动作。 | 置顶后选择器排序变化，窗口未获得始终置顶状态。 |
| FR-SESSION-011 | 删除活跃会话须先结束其 AI 工作和进程，再删除该会话记录；删除历史不删除用户输入/输出文件。 | 删除有运行任务的会话后进程停止、记录移除，任务生成的用户文件仍在原处。 |
| FR-SESSION-012 | 修改 hideBehavior 对下一次主动隐藏及之后持续生效；不追溯终止当前后台会话。 | keepAll 改为 endAll 不立即清空；下一次主动隐藏结束全部。 |

## 6. 手动命令与交互终端

| ID | 必须实现的行为 | 可验收场景 |
|---|---|---|
| FR-TERM-001 | 输入首个非空字符是半角 ! 时进入手动 terminal 模式；包含 ! 在内的全部输入显示绿色，并同时显示文字标识。 | 前置空白加 ! 可触发，全角 ！及文本中间 ! 不触发；颜色不是唯一标识。 |
| FR-TERM-002 | 提交时去掉该模式标记，其余命令内容交给当前 Session 的 PTY；仅有标记和空白不提交执行。 | ! 后的多参数、引号和管道保持用户原意；不会把 ! 当命令发出。 |
| FR-TERM-003 | 输入条的手动命令遵循 FR-CTX-006；终端面板直接传输按键、控制序列、粘贴及终端尺寸变化。 | 等待目录同步时新命令排队，但原始终端可继续交互和调整窗口。 |
| FR-TERM-004 | 首次打开终端或提交 ! 时按需创建持续 PTY，提供输出、真实提示符、控制键和交互程序支持；不为未使用终端的会话启动 shell 或伪造提示符。 | 纯 AI 会话无 PTY；打开终端后运行交互程序、输入回答、Ctrl+C、退出后仍回到同一 shell。 |
| FR-TERM-005 | 手动 ! 与终端面板的用户输入直通，不经过 AI 策略确认、不触发模型改写或 AI 白名单过滤。 | 两种 AI 策略下输入同一手动修改命令均直接到达 PTY；系统权限错误如实显示。 |
| FR-TERM-006 | 命令、输出、当前程序和会话生命周期关联；终止终端会话结束其管理的进程树。 | 子进程运行中结束会话，进程树被终止并形成可读历史状态。 |
| FR-TERM-007 | 为终端与自然语言输入分别处理输入法、粘贴及焦点；输入法预编辑不能触发提交或快捷操作。 | 中文候选确认不会提交；切回终端后控制键仍作用于终端。 |

### 7.2 仅两种 AI 策略

| ID | 必须实现的行为 | 可验收场景 |
|---|---|---|
| FR-POLICY-001 | 默认 readOnlyAutoConfirmChanges：只有可信、已知的只读操作免确认；任何修改、未知或无法可靠分类的 AI 操作都要求确认。 | 已知文件信息查询自动执行；改名、安装及未知 shell 在执行前等待用户。 |
| FR-POLICY-002 | yolo：全部 AI 操作免确认，包括修改、未知命令和 AI 发起的工具安装。策略切换后持续生效。 | 同一修改任务切换 yolo 后直接执行，不再显示确认步骤。 |
| FR-POLICY-003 | 确认展示将执行的命令/动作、已知文件变化、依赖安装和不能确定的影响；编辑计划/命令后重新判定。 | 确认后再编辑为另一操作，旧确认不自动授权新内容。 |
| FR-POLICY-004 | 策略只约束 AI；手动 ! 和终端面板直通。不能加入第三种“默认全确认”、按脚本永久批准清单或其它白名单旁路。 | 配置、UI、持久化和测试只接受两个值；手动终端不会弹 AI 确认。 |
| FR-POLICY-005 | AI 工具安装、卸载、系统/Git/网络/消息操作均使用同一策略。未知范围不能冒充精确文件预览。 | 默认策略安装工具、发送消息或推送 Git 均先确认；yolo 均免确认。 |
| FR-POLICY-006 | 免确认不等于绕过操作系统权限、外部身份认证、输入正确性或文件工具的明示约束；失败如实呈现。 | yolo 遇到未授权目录或未登录消息账号时说明条件不足，不声称已完成。 |

### 7.3 Run 生命周期

| ID | 必须实现的行为 | 可验收场景 |
|---|---|---|
| FR-RUN-001 | Run.state 采用 planning / awaitingInput / awaitingApproval / installing / queued / running / succeeded / partiallySucceeded / failed / cancelled / interrupted。依赖检查是 planning 子状态；结果摘要使用独立 summaryState，不把摘要阶段作为 Run 的唯一状态。 | 成功执行时 Run=succeeded，即使 summaryState 仍进行中或失败；批处理部分失败为 partiallySucceeded，并分别列项。 |
| FR-RUN-002 | 支持实时输出、确定进度/不确定进度和阶段信息；不能用估算百分比冒充工具实测。 | 无进度协议的命令显示运行状态，长输出持续可滚动。 |
| FR-RUN-003 | 取消传播到模型请求、下载、AI 任务和所管理进程；显示取消前已产生的输出与改动。 | 批量处理进行一半取消，已生成和未处理项分别列明。 |
| FR-RUN-004 | 多 Session 及多个 Run 支持并发并遵守默认值表。对可推导写集合的内置/结构化计划，冲突写入串行或报冲突；自由脚本不承诺识别全部写集合，按 unknown 及当前 AI 策略处理，手动终端保持直通。 | 两个结构化任务写同一文件时受保护；未知脚本默认策略确认、yolo 免确认，不展示虚假的全局写锁保证。 |
| FR-RUN-005 | 记录退出状态、工具错误、文件结果及可检查证据；不能只凭模型回答或零退出码认定目标已完成。 | 工具返回成功但预期文件缺失时任务不能标为完整成功。 |
| FR-RUN-006 | 重试创建新的 Run 并关联原记录，重新绑定显示给用户的上下文与策略；不把重试看成旧进程恢复。 | 失败任务切换目录后重试，显示新输入和关联关系。 |
| FR-RUN-007 | 原始输出、摘要、命令、输入上下文和结果入口在 UI-RUN-DETAIL 可回看；终端任务在 UI-TERMINAL 保留对应会话输出。 | 从任务记录可找到输入、执行内容和结果文件。 |

## 12. 范围控制

需求实现由 application、catalog、planner、policy、process、terminal、model、storage、platform 协作，具体契约见架构文档。UI 接收状态和用户意图，不直接承担业务执行。本文的验收不由旧 UI 静态文案、示例回调或浏览器预览测试替代。

仅实时语音明确下一版。能力台账的系统、Git、网络、消息和文件扩展全部属于首版；不得通过实现计划、平台条件或工具选择把已确认操作意图改成占位。必要参数和外部条件由能力合同明确，不能沿用历史固定示例替用户作决定。
